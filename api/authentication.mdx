All ScriptHub API requests require a Bearer token obtained from your dashboard. Tokens are scoped so you can grant only the permissions each integration needs. Keep your tokens secret — treat them with the same care as passwords.

## Generating a Token

<Steps>
  <Step title="Log in to your dashboard">
    Navigate to [scripthub.io/dashboard](https://scripthub.io/dashboard) and sign in to your account.
  </Step>
  <Step title="Open API Token settings">
    Go to **Settings > API Tokens** in the left sidebar.
  </Step>
  <Step title="Create a new token">
    Click **Generate New Token**, give it a descriptive name (for example, `ci-deploy` or `roblox-game`), and select the scopes your integration requires.
  </Step>
  <Step title="Copy your token">
    Copy the token immediately — it is only shown once. Store it somewhere safe, such as an environment variable or a secrets manager.
  </Step>
</Steps>

## POST /auth/token — Obtain an API Token Programmatically

If you prefer to generate tokens via the API rather than the dashboard, use this endpoint. This is useful for automated workflows or build systems.

**Request Body**

<ParamField body="email" type="string" required>
  The email address associated with your ScriptHub account.
</ParamField>

<ParamField body="password" type="string" required>
  Your ScriptHub account password.
</ParamField>

<ParamField body="scopes" type="array" required>
  An array of scope strings the token should be granted. See the [Token Scopes](#token-scopes) table below for valid values.
</ParamField>

```bash Generate Token via API
curl -X POST https://api.scripthub.io/v1/auth/token \
  -H "Content-Type: application/json" \
  -d '{
    "email": "you@example.com",
    "password": "your_password",
    "scopes": ["scripts:read", "scripts:write"]
  }'
```

```json Response
{
  "success": true,
  "data": {
    "token": "sh_live_abc123xyz",
    "scopes": ["scripts:read", "scripts:write"],
    "createdAt": "2024-01-15T10:00:00Z"
  }
}
```

<Warning>
  Sending credentials over the API to generate tokens is only appropriate in trusted server-side environments. Never call this endpoint from a Roblox game or client-side code.
</Warning>

## Passing the Token

Include the token in the `Authorization` header of every request:

```bash Example Request
curl -X GET https://api.scripthub.io/v1/scripts \
  -H "Authorization: Bearer sh_your_token_here"
```

```typescript TypeScript Example
const response = await fetch('https://api.scripthub.io/v1/scripts', {
  headers: {
    'Authorization': 'Bearer sh_your_token_here',
    'Content-Type': 'application/json'
  }
});
const data = await response.json();
```

## Token Scopes

When generating a token, select only the scopes your use case requires. Narrowly scoped tokens limit the blast radius if a token is ever compromised.

| Scope | Description |
|-------|-------------|
| `scripts:read` | Read script metadata and source |
| `scripts:write` | Create, update, and delete scripts |
| `scripts:execute` | Fetch private script loadstring content |
| `versions:read` | List and view script versions |
| `versions:write` | Restore versions |

## Error Responses

You will receive one of two authentication errors if a request cannot be authorized.

**`401 Unauthorized`** — the `Authorization` header is missing, malformed, or contains an invalid token.

**`403 Forbidden`** — the token is valid but does not have the scope required by the endpoint you called.

```json 401 Response
{
  "success": false,
  "error": {
    "code": "UNAUTHORIZED",
    "message": "No valid authentication token provided."
  }
}
```

<Warning>
  Never expose API tokens in client-side code or public repositories. Use environment variables or a secrets manager to inject tokens at runtime.
</Warning>
